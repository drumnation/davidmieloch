# AI-Native Interview Challenge: Backend Engineer

## Overview

This challenge involves the design and implementation of a backend system that leverages Language Model (LLM) AI to provide personalized recommendations to users. It tests your proficiency in backend development, AI integration, and problem-solving under a pair-programming setup.

### Context

Your task is to design a backend feature for a popular e-commerce platform. The platform wants to enhance their customer's shopping experience by providing personalized product recommendations using an AI Language Model (LLM).

### Challenge Parameters

- **AI Maturity Level:** Expert
- **Format:** Pair-programming
- **Time Limit:** 2-Hours
- **AI Tools Allowed:** Yes
- **Team AI Fluency:** Expert

## Challenge Description

Your task is to design and implement an API endpoint that will:

1. Accept as input a user's recent browsing history on the platform.
2. Leverage an LLM to generate personalized product recommendations based on the user's browsing history.
3. Return the generated recommendations in a suitable format to be consumed by the frontend.

## Implementation Requirements

- Use an appropriate backend language/framework (e.g., Node.js with Express, Python with Flask, etc.).
- Design an appropriate data model to represent the user's browsing history.
- Integrate with an LLM to generate personalized recommendations.
- Implement a REST API endpoint to receive the browsing history and return the generated recommendations.
- Write clean, maintainable, and well-documented code.
- Include basic error handling and validation for the API endpoint.

## Evaluation Rubric

### Technical Implementation (40%)
- **Excellent (35-40)**: Complete and robust implementation with efficient data modeling, intelligent LLM integration, and a well-designed API. Code is exceptionally clean, well-structured, and follows best practices.
- **Good (25-34)**: Functional implementation with solid data modeling and LLM integration. Code is clean and organized, with minor areas for improvement.
- **Satisfactory (15-24)**: Basic implementation with functional data modeling and LLM integration. Some areas could be improved for cleaner code or better organization.
- **Needs Improvement (0-14)**: Incomplete implementation or significant issues with data modeling or LLM integration. Code structure and organization need substantial improvement.

### AI Integration & Workflow (30%)
- **Excellent (25-30)**: Sophisticated AI usage that amplifies productivity and enhances the feature. Can explain AI prompt strategies, uses AI for multiple aspects of the challenge, and shows evidence of customizing/refining AI outputs.
- **Good (18-24)**: Effective AI usage that speeds up development and enhances the feature. Shows understanding of good prompting and how to integrate AI outputs with existing code.
- **Satisfactory (10-17)**: Basic AI usage that helps with simple tasks. Some understanding of how to prompt effectively but may accept AI outputs without sufficient review or adaptation.
- **Needs Improvement (0-9)**: Ineffective AI usage or over-reliance on AI without understanding. Code shows signs of directly using AI outputs without proper integration or review.

### Communication & Documentation (30%)
- **Excellent (25-30)**: Exceptional communication and documentation explaining design decisions, data model, and AI integration strategy. Easily collaborates in the pair-programming setup, and effectively articulates thought process and decision-making.
- **Good (18-24)**: Good communication and documentation with clear explanation of major design decisions. Works well in the pair-programming setup and can discuss AI usage and workflow.
- **Satisfactory (10-17)**: Basic communication and documentation that covers setup and usage but lacks depth on design decisions or AI workflow. Some difficulty in collaborating effectively in the pair-programming setup.
- **Needs Improvement (0-9)**: Poor communication or missing documentation. Struggles to collaborate effectively in the pair-programming setup.

## Interviewer Notes

### Key Questions to Ask

1. "Walk me through your data model. How did you decide on this structure?"
2. "Can you explain your process for integrating with the LLM? What were some challenges you faced?"
3. "Can you explain your process for working with AI tools during this challenge? What were some effective prompts or strategies you used?"
4. "What validation or error handling have you implemented for the API endpoint? Why did you choose this approach?"
5. "If you had more time, what additional features or improvements would you make?"

### Red Flags

- Unable to explain parts of their own code (indicates over-reliance on AI without understanding)
- Poor data model design indicating lack of understanding of the problem
- Ineffective or incorrect usage of the LLM for generating recommendations
- No consideration for error handling or edge cases in the API endpoint
- Difficulty in collaborating or communicating effectively in the pair-programming setup

### Green Flags

- Thoughtful and efficient data model design
- Strategic use of AI tools that enhances rather than replaces their own thinking
- Effective integration with the LLM to generate meaningful recommendations
- Robust error handling and validation for the API endpoint
- Excellent collaboration and communication skills in the pair-programming setup
