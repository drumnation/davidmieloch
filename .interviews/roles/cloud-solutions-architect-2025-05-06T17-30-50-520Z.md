# AI-Native Interview Challenge: Cloud Solutions Architect

## Overview

Design a cloud-based architecture for a mobile, customer-facing dashboard of a SaaS product that visualizes analytics data and allows users to create custom reports. This challenge evaluates your ability to design scalable, efficient and secure cloud architectures for mobile applications.

### Context

Developing a customer-facing dashboard for a SaaS product that visualizes analytics data and allows users to create custom reports.

### Challenge Parameters
- **AI Maturity Level:** Intermediate
- **Format:** Pair-programming
- **Time Limit:** 2 Hours
- **AI Tools Allowed:** No
- **Team AI Fluency:** Novice

## Challenge Description

Design a cloud-based architecture for a mobile application that:

1. Provides real-time analytics data to the users.
2. Allows users to create, save and share custom reports.
3. Ensures data privacy and security.
4. Handles high volume of data and user traffic.
5. Is cost-effective and easy to maintain.

## Implementation Requirements

- Use AWS services for the architecture design.
- Ensure the architecture is scalable to handle high volume of data and user traffic.
- Implement proper security measures to protect sensitive data.
- Use managed services where possible to reduce maintenance overhead.
- Include considerations for cost optimization.

## Evaluation Rubric

### Architectural Design (40%)
- **Excellent (35-40)**: Complete and detailed design with considerations for scalability, security, cost optimization, and maintenance. Shows deep understanding of AWS services and architecture best practices.
- **Good (25-34)**: Solid design with key components well implemented. Shows good understanding of AWS services. Some areas could be refined for better scalability, security, cost or maintenance.
- **Satisfactory (15-24)**: Basic design with essential components implemented. Some understanding of AWS services. Significant areas could be improved for scalability, security, cost or maintenance.
- **Needs Improvement (0-14)**: Incomplete or flawed design. Lacks understanding of AWS services or architecture best practices. Significant improvements needed for scalability, security, cost or maintenance.

### Technical Communication (30%)
- **Excellent (25-30)**: Excellent communication explaining design decisions, architectural components, and their interaction. Includes detailed diagram and clear explanation of AWS service choices.
- **Good (18-24)**: Good communication with clear explanation of architecture design and AWS service choices. Diagram could be more detailed or explanation could be clearer.
- **Satisfactory (10-17)**: Satisfactory communication with basic explanation of architecture design and AWS service choices. Diagram and explanation lack detail.
- **Needs Improvement (0-9)**: Poor communication with unclear or incorrect explanation of architecture design and AWS service choices. Diagram is missing or incorrect.

### Problem Solving & Decision Making (30%)
- **Excellent (25-30)**: Exceptional problem-solving skills and decision-making. Can explain trade-offs for each decision and shows deep understanding of the problem domain.
- **Good (18-24)**: Good problem-solving skills and decision-making. Can explain most decisions and shows understanding of the problem domain.
- **Satisfactory (10-17)**: Basic problem-solving skills and decision-making. Can explain some decisions but lacks depth in understanding of the problem domain.
- **Needs Improvement (0-9)**: Poor problem-solving skills and decision-making. Struggles to explain decisions or shows lack of understanding of the problem domain.

## Interviewer Notes

### Key Questions to Ask

1. "Can you walk me through your architecture design? How did you decide on this structure?"
2. "How did you ensure the architecture is scalable and can handle high volume of data and user traffic?"
3. "What security measures did you implement to protect sensitive data?"
4. "How did you optimize costs in your architecture design?"
5. "What managed services did you use and why?"

### Red Flags

- Unable to explain parts of their architecture design
- Did not consider scalability, security, cost, or maintenance in their design
- Lack of understanding of AWS services
- Did not use managed services where appropriate
- Not considering data privacy and security

### Green Flags

- Thoughtful architecture design showing deep understanding of AWS services and architecture best practices
- Consideration of scalability, security, cost, and maintenance in the design
- Good use of managed services to reduce maintenance overhead
- Excellent communication skills explaining design decisions and AWS service choices
- Strong problem-solving skills and decision-making
