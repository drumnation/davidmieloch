# AI-Native Interview Challenge: Cloud Solutions Architect

## Overview

Design and implement a scalable, secure, and highly available backend for a customer-facing dashboard that visualizes analytics data and allows users to create custom reports. This challenge evaluates your ability to design and implement cloud-native solutions, manage data, and implement secure and efficient APIs.

### Context

You are working on a SaaS product that provides analytics data to customers. Your task is to design the backend for a dashboard that visualizes this data and allows users to create custom reports.

### Challenge Parameters
- **AI Maturity Level:** Advanced
- **Format:** Pair-Programming
- **Time Limit:** 4 Hours
- **AI Tools Allowed:** No
- **Team AI Fluency:** Expert

## Challenge Description

In this challenge, you are expected to:

1. Design a scalable and robust cloud architecture for the backend system.
2. Implement a secure API endpoint to retrieve analytics data.
3. Design and implement data storage and retrieval mechanisms for the analytics data.
4. Implement an API endpoint for users to create, update, and retrieve custom reports.

## Implementation Requirements

- Use a cloud platform of your choice.
- Implement RESTful API endpoints.
- Implement proper data storage and retrieval mechanisms.
- Implement proper error handling and data validation.
- Ensure the security of user data.
- Write clean, maintainable, and well-documented code.

## Evaluation Rubric

### Technical Implementation (40%)
- **Excellent (35-40)**: Complete implementation with advanced features like efficient data retrieval, exceptional error handling, and optimized performance. Code is exceptionally clean, well-structured, and follows best practices.
- **Good (25-34)**: Solid implementation with all core features working well. Code is clean, well-organized, and follows good practices.
- **Satisfactory (15-24)**: Basic implementation with core functionality working. Some areas could be improved for cleaner code or better organization.
- **Needs Improvement (0-14)**: Incomplete implementation or significant issues with core functionality. Code structure and organization need substantial improvement.

### Cloud Architecture & Workflow (30%)
- **Excellent (25-30)**: Sophisticated architecture design that ensures scalability, security, and high availability. Clear understanding of cloud-native design principles and best practices.
- **Good (18-24)**: Effective architecture design that meets basic requirements of scalability and security. Shows understanding of cloud-native principles.
- **Satisfactory (10-17)**: Basic architecture design that meets some requirements but lacks robustness. Some understanding of cloud-native principles.
- **Needs Improvement (0-9)**: Ineffective architecture design or lack of understanding of cloud-native principles.

### Communication & Documentation (30%)
- **Excellent (25-30)**: Exceptional documentation explaining design decisions, cloud architecture, and data management. Includes detailed README, inline comments where appropriate, and clear commit messages.
- **Good (18-24)**: Good documentation with clear README and explanation of major design decisions. Some discussion of data management.
- **Satisfactory (10-17)**: Basic documentation that covers setup and usage but lacks depth on design decisions or data management.
- **Needs Improvement (0-9)**: Minimal or missing documentation. Hard to understand code structure or design decisions.

## Interviewer Notes

### Key Questions to Ask

1. "Walk me through your cloud architecture. How did you ensure scalability, security, and high availability?"
2. "How did you design the data storage and retrieval mechanisms for the analytics data?"
3. "How did you ensure the security of the API endpoints and user data?"
4. "What was the most challenging part of this implementation, and how did you overcome it?"
5. "If you had more time, what additional features or improvements would you make?"

### Red Flags

- Unable to explain parts of their own code or architecture (indicates lack of understanding)
- Poor architecture design showing lack of understanding of cloud-native principles
- No consideration for data security, error handling, or data validation
- Not leveraging cloud platform capabilities effectively

### Green Flags

- Thoughtful architecture design showing deep understanding of cloud-native principles
- Effective data storage and retrieval mechanisms
- Well-structured code with clear separation of concerns
- Consideration of security, scalability, and high availability
- Bonus points for additional features or enhancements that weren't explicitly required
