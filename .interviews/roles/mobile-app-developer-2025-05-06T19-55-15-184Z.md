# AI-Native Interview Challenge: Mobile App Developer

## Overview

Design and implement a backend for a mobile app that integrates with IoT devices and displays real-time data from sensors. This challenge evaluates your ability to work with real-time data, API design, and database schema design in a backend context.

### Challenge Parameters
- **AI Maturity Level:** Intermediate
- **Format:** Take-home Challenge
- **Time Limit:** 4 Hours
- **AI Tools Allowed:** No
- **Team AI Fluency:** Proficient

## Challenge Description

Create a backend application that:

1. Provides APIs for a mobile app to fetch real-time data from IoT sensors.
2. Manages multiple IoT devices and allows addition or removal of devices.
3. Stores real-time data in a database and provides historical data on request.
4. Handles errors and exceptions gracefully and securely.

## Implementation Requirements

- Use Node.js with Express or a similar framework
- Implement RESTful APIs for device management and data retrieval
- Use a database (SQL or NoSQL) for storing IoT device details and sensor data
- Implement error handling and validation for the APIs
- Write clean, maintainable, and well-documented code
- Include unit tests for key features

## Evaluation Rubric

### Technical Implementation (40%)
- **Excellent (35-40)**: Complete implementation with advanced features like optimized database schema, efficient data retrieval, and solid security measures. Code is exceptionally clean, well-structured, and follows best practices.
- **Good (25-34)**: Solid implementation with all core features working well. Code is clean, well-organized, and follows good practices.
- **Satisfactory (15-24)**: Basic implementation with core functionality working. Some areas could be improved for cleaner code or better organization.
- **Needs Improvement (0-14)**: Incomplete implementation or significant issues with core functionality. Code structure and organization need substantial improvement.

### AI Integration & Workflow (30%)
- **Excellent (25-30)**: Sophisticated AI usage that amplifies productivity. Can explain AI prompt strategies, uses AI for multiple aspects (code, testing, design thinking), and shows evidence of customizing/refining AI outputs.
- **Good (18-24)**: Effective AI usage that speeds up development. Shows understanding of good prompting and how to integrate AI outputs with existing code.
- **Satisfactory (10-17)**: Basic AI usage that helps with simple tasks. Some understanding of how to prompt effectively but may accept AI outputs without sufficient review or adaptation.
- **Needs Improvement (0-9)**: Ineffective AI usage or over-reliance on AI without understanding. Code shows signs of directly using AI outputs without proper integration or review.

### Communication & Documentation (30%)
- **Excellent (25-30)**: Exceptional documentation explaining design decisions, API architecture, and AI integration strategy. Includes detailed README, inline comments where appropriate, and clear commit messages.
- **Good (18-24)**: Good documentation with clear README and explanation of major design decisions. Some discussion of AI usage and workflow.
- **Satisfactory (10-17)**: Basic documentation that covers setup and usage but lacks depth on design decisions or AI workflow.
- **Needs Improvement (0-9)**: Minimal or missing documentation. Hard to understand code structure or design decisions.

## Interviewer Notes

### Key Questions to Ask

1. "Walk me through your API design. How did you decide on this structure?"
2. "How did you approach the database schema design for this application? What alternatives did you consider?"
3. "Can you explain your process for handling real-time data in this challenge?"
4. "What was the most challenging part of this implementation, and how did you overcome it?"
5. "If you had more time, what additional features or improvements would you make?"

### Red Flags

- Unable to explain parts of their own code (indicates over-reliance on AI without understanding)
- Direct copying of AI-generated code without adaptation to the specific requirements
- Poor API design or database schema showing lack of architectural thinking
- No consideration for error handling or security
- Not leveraging Node.js effectively for backend development

### Green Flags

- Thoughtful API design showing understanding of REST principles and best practices
- Strategic use of database schema that allows for efficient data retrieval and storage
- Evidence of iterative improvement and learning during the development process
- Well-structured code with clear separation of concerns
- Consideration of security, performance, and user experience
- Bonus points for additional features or enhancements that weren't explicitly required
